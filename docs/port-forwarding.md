# 端口转发与占用检查

## 转发方式与地址族

- **内核加速（IPv4 + IPv6）**：由路由器内核 NAT 转发 TCP / UDP，不经 LinkNest 进程复制数据。每条规则选择「仅 IPv4」或「仅 IPv6」，目标必须是同地址族的非本机单播 IP。IPv6 目标填写 `[2001:db8::20]:6881`；不支持域名、IPv6 链路本地目标或 IPv4 / IPv6 互转。双地址族可建立相同端口的两条规则。
- **兼容转发（IPv4 + IPv6 + 域名）**：支持 IPv4 → IPv4、IPv6 → IPv6、IPv4 → IPv6、IPv6 → IPv4；TCP / UDP 均支持，目标也可填域名。监听地址族只约束入站连接，目标地址族独立。双栈监听可同时接收两种来源并转发到同一目标。

相同端口允许创建多条规则，前提是协议、地址族或监听地址不重叠。例如 `0.0.0.0:6881` 仅 IPv4 与 `[::]:6881` 仅 IPv6 可以共存并分别选择转发方式。双栈 `[::]:6881` 同时占用两种地址族，不能再叠加任一地址族的同协议规则。TCP 与 UDP 可以使用相同端口；TCP + UDP 同时占用这两个协议。不同指定监听 IP 也可共用端口，但同地址族的通配监听会与指定 IP 重叠。

内核模式需 Linux host 网络、防火墙权限和对应地址族的转发开关及 legacy NAT 模块。IPv6 使用 `ip6tables-legacy`，IPv4 使用 `iptables-legacy`；应用先检查规则能否解析，再写入自有链。缺少 IPv6 NAT 能力、权限或转发开关时明确报错，不会自动修改系统开关或改用兼容转发。两个地址族分别应用和清理，一侧失败不撤销另一侧成功的内核规则。

## 保留客户端原始 IP

内核模式可开启「保留客户端原始 IP」。开启后只执行目标地址转换，不添加 LinkNest 的来源地址转换，支持 IPv4 和 IPv6。后端回程必须经过同一路由器；同网段通过路由器地址回访时，后端可能直接回复客户端，需要正确的回程路由。后续 Docker 用户态代理或其他设备仍可能改写来源，需端到端核对。

该选项默认关闭，以保留现有规则行为：路由器对 LinkNest 转发的数据执行来源地址转换。兼容转发重新建立到后端的连接，后端看到转发器地址，不支持保留原始来源 IP，也不会往任意 TCP / UDP 数据中插入 `X-Forwarded-For` 或 PROXY 协议内容。配置导出与导入保留内核规则的原 IP 选项。

## 占用检查

启用防火墙管理并使用 host 网络时，LinkNest 在应用配置及周期复查时读取路由器 IPv4 / IPv6 的 legacy NAT 规则。除了本机监听，还检查从 PREROUTING 可达的 DNAT / REDIRECT，包括 UPnP / PCP 映射。这些映射不占用监听 socket，不能仅靠 bind 成功判断转发正常。

同一协议、监听地址和端口范围存在重叠时，显示具体协议、端口、冲突链和目标。即使目标相同，也不能让两个服务同时管理这条映射。LinkNest 保留配置，但不启动冲突转发；用户自行更换端口或调整外部映射后，会在下次检查自动重试。不会自动删除 UPnP、UCI 或 Docker 的规则。

只忽略 LinkNest 自有 NAT 链、未挂接的链、OUTPUT 专用映射，以及明确不相交的协议 / 地址 / 端口。复杂的来源、网卡等匹配按“可能冲突”保守处理，不保证模拟防火墙每条规则的最终命中顺序。扫描失败不标记为正常；未授权防火墙或非 host 部署无法核对宿主路由器 NAT。当前检查针对 legacy iptables，不涵盖其他独立 nftables / 硬件转发控制面。

内核 NAT 转发本身不创建监听 socket；在 `netstat` 没有监听是正常的。状态中的“本机 TCP / UDP 监听冲突”与“NAT 映射冲突”是两种不同情况。连接跟踪可能在规则变更后保留已有会话；请重新建立连接验证，不清空整个 conntrack 或防火墙。
