# 端口转发与占用检查

启用防火墙管理并使用 host 网络时，LinkNest 在应用配置及周期复查时读取路由器 IPv4 / IPv6 的 legacy NAT 规则。除了本机监听，还检查从 PREROUTING 可达的 DNAT / REDIRECT，包括 UPnP / PCP 映射。这些映射不占用监听 socket，不能仅靠 bind 成功判断转发正常。

同一协议、监听地址和端口范围存在重叠时，显示具体协议、端口、冲突链和目标。即使目标相同，也不能让两个服务同时管理这条映射。LinkNest 保留配置，但不启动冲突转发；用户自行更换端口或调整外部映射后，会在下次检查自动重试。不会自动删除 UPnP、UCI 或 Docker 的规则。

只忽略 LinkNest 自有 NAT 链、未挂接的链、OUTPUT 专用映射，以及明确不相交的协议 / 地址 / 端口。复杂的来源、网卡等匹配按“可能冲突”保守处理，不保证模拟防火墙每条规则的最终命中顺序。扫描失败不标记为正常；未授权防火墙或非 host 部署无法核对宿主路由器 NAT。当前检查针对 legacy iptables，不涵盖其他独立 nftables / 硬件转发控制面。

内核 NAT 转发本身不创建监听 socket；在 `netstat` 没有监听是正常的。状态中的“本机 TCP / UDP 监听冲突”与“NAT 映射冲突”是两种不同情况。连接跟踪可能在规则变更后保留已有会话；请重新建立连接验证，不清空整个 conntrack 或防火墙。
