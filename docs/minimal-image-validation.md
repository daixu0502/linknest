# 精简镜像验证

2026-10-21 在 ARM64、Linux 4.4.60 路由器 Docker 中验证。候选镜像 Docker 显示约 24.7 MB；最终发布采用同一运行依赖选择逻辑。镜像未使用 UPX，程序与前端功能均保留。

测试应用、客户端、后端使用独立容器、网络及新数据卷；实际转发走专用 veth 链路，不使用生产防火墙或生产数据卷。带 NET_ADMIN / NET_RAW 的测试应用仅管理自己的网络命名空间；外网 TLS 探针无额外权限、不监听端口，只读访问 ACME 目录。

通过的检查包括：

- 初始化、登录、配置保存、前端资源、健康检查和重启恢复。
- IPv4 → IPv6、IPv6 → IPv4 的 TCP / UDP 兼容转发；域名目标回归。
- IPv4 / IPv6 同端口分别建立内核 TCP / UDP 转发，关闭原 IP 时后端看到测试路由器，开启时看到测试客户端的实际 IPv4 / IPv6。
- HTTP 路径、查询参数、X-Forwarded-For；WebSocket 子协议、文本与二进制数据；WS/WSS、来源保护及后端证书校验回归。
- HTTPS 监听、证书导入、ZIP 中完整证书与私钥、系统 CA 及多个时区；真实 Let’s Encrypt 目录 HTTPS 验证。
- legacy iptables/ip6tables、restore 工具及 xtables 插件实际运行；无缺失动态库或插件错误。
- 原有 LinkNest 与管理代理的容器 ID、镜像 ID、进程和运行状态保留，原厂 UPnP 配置及服务保持；测试规则退出后清理。

测试程序、临时配置和凭据只在本地保留，不收入源码提交和安装包。此验证未替代所有 Linux 内核、其他架构或任意第三方防火墙策略上的兼容测试；内核转发仍需要宿主系统支持对应地址族 NAT。
