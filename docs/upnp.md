# 路由器 UPnP 管理

入口：**端口转发 → 路由器 UPnP**，地址栏为 `#/forwards/upnp`。接入路由器原有 MiniUPnPd / IGD 服务，不另起 UPnP 守护进程，不自动接管设备映射。

## 连接与映射

在“连接设置”填写设备描述地址，例如 `http://192.168.1.1:5351/rootDesc.xml`。只支持内网或回环 IPv4 HTTP 地址，不使用系统代理、不跟随重定向、不接受跨地址控制 URL。启用的是管理功能，不会替你开启路由器原厂 UPnP。

在小米 AX9000 本机部署时，原厂接口绑定 LAN 网卡，选择 `br-lan`；容器使用 host 网络并保留 `NET_RAW`。部署在另一台局域网设备上通常不需要绑定网卡。不需要新增 privileged、host PID 或 Docker Socket。

- 显示原厂映射的协议、外部端口、目标 IP/端口、描述和剩余租期；最多读取 512 条，超过或读取失败时明确提示。
- 添加 / 删除 / 编辑直接调用原厂 SOAP 接口。编辑需先核对旧记录，再删除并重建；失败时尝试恢复，并显示恢复结果。不会覆盖已发现的其他设备映射。标准接口没有跨请求事务，仍存在第三方设备同时变更的竞争窗口。
- 新映射与已启用 LinkNest 监听端口冲突时拒绝创建；路由器端的其他权限与冲突也会显示具体 UPnP 错误码。
- 每条映射对应 TCP 或 UDP。租期 0 表示不按时到期，不保证重启后保留；重启恢复取决于原厂租约机制。
- 原厂若强制“安全模式”，可能禁止管理其他设备的映射。LinkNest 不会自动关闭该保护，拒绝时请在原厂配置中核对。

页面提供“允许跨设备管理映射”开关，初始关闭。关闭时前后端都只允许修改实际 HTTP 请求来源本机的映射，其他设备映射仅显示；不是根据浏览器或 X-Forwarded-For 判断本机。

开启需管理员二次验证和一次性 root SSH 凭据，会明确提示降低局域网设备之间的映射隔离。只适配已核实的 OpenWrt MiniUPnPd 启动脚本：调整原厂 `secure_mode` 和对应 `-S` 启动参数，备份租约、短暂重启 UPnP，再核对原有映射；核对通过后才确认。关闭开关恢复安全模式。映射缺失、取消或 SSH 中断会请求回滚，不自动接受未知格式脚本或变化后的主机指纹。

模式设置持久到原厂配置和启动脚本，不额外安装服务；固件更新可能覆盖启动脚本。页面显示最近成功设置，不代表持续读取了原厂状态。停用管理模块不会自动恢复安全模式。流程回滚不能保证突然断电等情况下的硬件级事务一致性；变更前请保留原厂配置备份。

## 设备黑名单

支持私网 IPv4、私网网段和单播 MAC，MAC 可使用冒号、短横线、点分隔等常见格式。保存名单仅生成待应用配置；点击“应用到路由器”才改变路由器。

应用需要管理员密码、已启用时的 2FA，以及与 UPnP 路由器 IP 相同、已核实指纹的 root SSH 主机。SSH 主机可先在 Web 终端添加并确认指纹；密码或未加密私钥只用于本次操作，不写入数据卷，也不自动信任变化后的指纹。

黑名单限制设备到路由器 UPnP HTTP 控制端口和 UDP 5351（NAT-PMP/PCP）的请求，不封锁该设备普通上网或所有 SSDP/DLNA 广播。要求独立的 1024 以上 HTTP 端口。MAC 过滤只适用于路由器能直接看到设备二层 MAC 的场景；经其他路由/NAT 时使用对应 IP。它不是防 MAC/IP 伪造的网络准入控制。

原厂持久配置写入 `/etc/config/firewall` 中带 `lnupnp_` 前缀及 `linknest_owner=upnp-v1` 的规则。只替换自身规则，保留其他配置及 `/etc/config/upnpd` 的原厂名单。原厂 fw3 在防火墙重载或路由器重启后加载持久规则；LinkNest 停止不撤销这些限制。

立即应用只更新 `LNEST_UPNP` 自有 IPv4/IPv6 INPUT 链，不刷新整个防火墙，不重启 MiniUPnPd。先执行暂存配置及 `iptables-restore --test` 检查；有未提交配置、检测到并发修改或应用失败时中止/尝试回滚。复杂环境仍应保留路由器原厂配置备份。

默认保留已经存在的映射。应用时可单独勾选删除：只删除能确认匹配名单的映射；MAC 无法识别、读取不完整或服务拒绝删除时保留并提示。单纯删除映射不能防止设备重新申请。IPv6 IGD 防火墙 pinhole 管理不属于本版功能。

## 数据与验证

管理设置、待应用名单、最近成功应用记录保存在 `/data/upnp/config.json`，随整个 LinkNest 数据卷备份。页面“已写入原厂配置”表示最近操作成功，不等于持续实时核验宿主配置；手动修改原厂规则或恢复出厂设置后，请重新核对与应用。恢复 LinkNest 数据卷不会自动向路由器写规则。

回归：`go test ./...`、`node scripts/test-upnp.mjs`，以及可选 Playwright `node scripts/test-dialog-layout.cjs`。Linux 模拟 UCI/iptables 验证成功、预检查失败、实际应用失败回滚、并发修改和同名规则保护。可选 `LINKNEST_UPNP_LIVE_URL` / `LINKNEST_UPNP_LIVE_INTERFACE` 只读检查真实路由器；`LINKNEST_UPNP_NATIVE_DRY_RUN=1` 仅在明确的 OpenWrt 测试环境执行原厂暂存及 `--test`，不安装规则。
